## Обязательная проверка до изменений БД

Доступ из Friendly Halimede пока отсутствует: содержимое/потребители default_db **не проверены**. Подготовлен read-only `node timeweb/import/private-run.js --inspect`: counts schemas/objects/functions/connections и имена обычных/partitioned/materialized таблиц с количеством строк, BEGIN READ ONLY, statement_timeout5s, проверка db/role/server IP; содержимое строк не выводится. Views/foreign tables не исполняются для подсчёта, чтобы не запускать чужой SQL/внешние запросы. При timeout проверка не считается завершённой. Выполнить из контейнера backend после отдельно разрешённого размещения в этой сети, не с Мака напрямую. До этого подготовка/первичный запуск shell продолжаются, SQL изменения запрещены. Новый сервер для проверки не нужен. Способ открытия shell/exec именно этого контейнера надо подтвердить в панели/поддержке; наличие такой возможности пока не проверено. Панельный интерфейс может помочь проверить counts, но источник/права надо подтвердить. Инвентаризировать у владельца приложения, cron, integrations и выключенные consumers; ноль соединений этого не доказывает.

Любые неизвестные объекты/данные/соединения: отказ, ничего не TRUNCATE/DROP/перезаписывать. Проверка учитывает даже пустые чужие таблицы, не только строки. После read-only проверки и подтверждения владельцем неиспользования вручную задать MIGRATION_DB_CONTENTS_CONFIRM=owner-verified-empty-and-unused только для ручного оператора, не в постоянный Compose.

## Явный режим без TLS

MIGRATION_ENV=private; MIGRATION_PG_TLS=disabled-private; MIGRATION_PRIVATE_CONFIRM=Friendly-Halimede-default_db-gen_user. URL строго postgresql://gen_user:<private-password>@192.168.10.4:5432/default_db без query parameters. Неверные host/db/user/port/TLS selector отвергаются. ssl=false выбирается по этому режиму, без попытки TLS и без fallback. Старый staging verify-full сохранён. Frontend HTTPS обязателен; cookie Secure/HttpOnly/SameSite/CSRF и проверки сессии/курса сохранены.

Один gen_user у API/auth/worker/ручного оператора означает отсутствие прежней DB изоляции ролей. Трафик БД plaintext только внутри выбранной сети; public IP БД не включать. Не считать сеть защитой содержимого от её других участников. Не передавать DB URL frontend/build args, не печатать секреты.

## Ручной импорт и миграции

Обычный root docker-compose.yml запускает только3 services. Нет migrate/seed/import, entrypoint их не вызывает: рестарт/повторный deploy не запускает SQL импорт или миграции. До проверки/импорта API и worker запускают private-boot.js: только liveness200/readiness503, **без подключения к БД и без writes**, frontend доступен. MIGRATION_DB_READY_CONFIRM оставлять пустым. После разрешённой проверки и ручного импорта установить verified-and-initialized-default_db и перезапустить приложение; только тогда работают API/worker. Нельзя считать waiting режим готовым сайтом. Предыдущий synthetic TLS manifest сохранён в deploy/timeweb/synthetic-tls.compose.yml как альтернативный архив плана.

Для существующего архива **не запускать сначала пустую миграцию**: reviewed importer сам создаёт схемы001–005 и данные одной транзакцией. Ручная команда оператора:
`node timeweb/import/private-run.js --execute`
Приватные operator variables: MIGRATION_IMPORT_CONFIRM=import-reviewed-backup-once, MIGRATION_DB_CONTENTS_CONFIRM выше, MIGRATION_DUMP_PATH=абсолютный путь к read-only privately supplied database.dump, MIGRATION_PG_BIN=директория pg_restore17; остальные private app config variables. Использовать существующий проверенный `~/Minenkov-backup/20261009-224214/database.dump`, не изменять его и не добавлять в образ/Git/logs. Передача копии в разрешённый операторский процесс и реальный импорт требуют отдельного разрешения; сейчас не выполняются. Runtime image не содержит pg_restore: нужны разрешённый private-network оператор с pg_restore17 или отдельный вручную запускаемый одноразовый операторский образ; не утверждать наличие shell/exec App Platform без проверки панели/поддержки. Если разрешённого канала нет — импорт блокирован, приложение ещё не готово работать с перенесёнными данными.

Importer проверяет server/db/user, пустоту и подтверждение владельца; повторяет проверку под advisory lock в транзакции. Повтор на уже импортированной БД отказывается. Записывает ledger/checksums вместе с import_runs в тот же commit; ошибка откатывает данные/схемы. UUID/связи/даты/хеши сохраняются, старые sessions/reset tokens не импортируются. Пять legacy active personal-program сохраняются по решению владельца, mode unknown/source legacy migration, никаких payments/mail; шесть videos сохраняются без назначения курса. Реальные пароли входом не проверены. Сами media storage файлы пока не переносятся, Kinescope disabled.

После импорта только явно разрешённые будущие schema updates: `node timeweb/migrate.js`, MIGRATION_MIGRATION_CONFIRM=isolated-rehab-schema и owner confirmation; отдельного пользователя не требует. Ledger/checksum делает повтор безопасным, untracked schema отвергается. Для этой конфигурации --grants/--synthetic-seed запрещены. SQL изменения не выполняются при boot.
