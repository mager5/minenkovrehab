## Неоднозначности, без назначения прав

- 5 пользователей не имеют profile в исходнике. Они сохранены, пустые/новые
  профили не создавались; требуется явное решение о профиле и отображении имени.
- 5 исторических покупок не имеют достоверного test/live. Сохраняются с mode=NULL
  и исходным status; соответствующие access queries не дают права. Нужна сверка
  режима по подтверждённым внешним платёжным данным в отдельно разрешённом этапе.
- В дампе нет связи videos → product/lesson. Все 6 видео сохранены с владельцами,
  но course_videos остаётся пустой. Названия/path не использованы для угадывания
  курса; нужен утверждённый mapping и Kinescope catalogue.
- 10 identities имеют provider email; OAuth providers: 0, SSO users: 0,
  anonymous users: 0. Это сведения снимка, не доказательство production settings.
- 1 email не подтверждён. Исходное состояние сохранено; собственный signin
  не выпускает ему сессию. Требуется отдельный workflow подтверждения/приглашения,
  восстановление пароля само по себе не выставляет email_confirmed_at.
- Source role/is_super_admin/app/user metadata не дают новых admin прав.
  Настройка администраторов требует явного доверенного списка UUID и проверки.

## Атомарность и защита

| Проверка | Итог |
|---|---|

| Изменение архива | Не обнаружено |

При первых пробах guard неверно сравнивал PostgreSQL inet text (с суффиксом
маски) с host и различал системные symlink временных каталогов macOS. Он
отказывался до записи. Исправлено: host(inet_server_addr()) и realpath;
в последней репетиции все проверки успешны. Данные ошибок не выводились.

## Браузер: отдельная синтетическая база

Headless Chrome через pinned playwright-core, новый изолированный профиль.
Разрешён только локальный origin Next.js; все внешние запросы браузера блокируются,
trace/screenshots/console с чувствительными полями не сохраняются.

Проверены реальные формы и взаимодействия: вход → SSR кабинет → запрет чужого
курса → страница продукта → оба согласия → checkout → pending статус → выход
через меню профиля → запрет кабинета → форма forgot → TestSender в памяти →
форма reset по одноразовой ссылке → вход новым синтетическим паролем.
Checkout оставляет один pending order и ноль purchases; success page не выдаёт
доступ. Email/токен/пароли искусственные, их значения не выводятся.

В первых браузерных прогонах тест подтверждал только одно из двух согласий,
затем переходил со страницы до завершения асинхронного logout. Исправлен тест:
оба реальных согласия, устойчивое взаимодействие с hover-меню, ожидание ответа
logout и перехода. Не использованы подмена API или JS-вызов logout в обход UI.

Финальный regression: **38/38 прошли, 0 ошибок, 0 пропусков** (21 payment,
14 auth/SSR/browser/imported-state, 3 import parser/preflight/guard). Реальные письма/платежи, реальные аккаунты в браузере,
Kinescope playback и OAuth/регистрация через интерфейс не проверялись.
