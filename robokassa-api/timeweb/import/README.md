# Локальная репетиция импорта

Из корня проекта:

```sh
node robokassa-api/timeweb/import/rehearse.js /Users/imax/Minenkov-backup/20261009-224214/database.dump
```

Либо из robokassa-api: `npm run rehearse:import -- /полный/путь/database.dump`.
Нужны Node 20+, установленный backend node_modules и PostgreSQL 17 tools
в `/opt/homebrew/opt/postgresql@17/bin`. Скрипт не читает .env, DATABASE_URL,
PGHOST или конфигурацию рабочих сервисов. Никакого режима внешней БД нет.

Создаётся отдельный временный кластер и случайная база `rehab_import_<random>`.
PostgreSQL слушает только 127.0.0.1 на свободном порту, TCP защищён отдельным
случайным SCRAM-паролем, каталог и временный password file закрыты от других
пользователей. Guard сверяет БД, серверный loopback, реальный data_directory
собственного кластера и nonce marker. Импорт в другую БД запрещён ещё до записи.
После проверки кластер останавливается, каталог (включая WAL/пароль/log) удаляется.
Ошибка команды initdb/pg_ctl выводится обобщённо; сообщения SQL со строками данных
не выводятся. Для кластера отключены statement/error/parameter logs. При SIGINT
и SIGTERM также выполняется cleanup. SIGKILL/отключение машины не позволяют
выполнить finally: оставшийся закрытый временный каталог потребуется удалить
после проверки отсутствия своего процесса, не публиковать его и не добавлять в Git.

Архив читается pg_restore только для COPY шести выбранных таблиц. Ни DDL, ни
произвольный SQL из архива не исполняется. COPY decoding сохраняет \N/empty,
табуляции, переводы строк, слеши. Открытые значения остаются в памяти процесса
и временной БД; отчёт содержит только счётчики. Сессии, confirmation/recovery/
email-change/reauth tokens, MFA/refresh/flow/служебные объекты не переносятся.

В одной транзакции применяются собственные 001/002/003, вставляются UUID/поля,
credentials без изменения, identities, metadata, проверяются количества и
точное SQL-равенство каждого поля/хеша, затем import_runs marker и commit.
Дата проверяется PostgreSQL, без округления JS Date; цена проверяется как numeric.
Advisory lock сериализует конкурентные imports. Повтор безопасно отказывается,
никаких upsert/дедупликаций существующих пользователей/покупок нет. Сбой, включая
SQL constraints, откатывает и данные, и создание rehab schema. Marker guard
остаётся только в временной пустой БД до следующей попытки.

Историческим покупкам сохраняются status и invoice, но mode=NULL: старый дамп
не доказывает test/live. Access predicates NULL не допускают. Course mappings
не создаются из названий/path. Отсутствующие profiles не синтезируются. Roles/
metadata хранятся только как исходные сведения и не используются для назначения
администраторов. У непроверенного email login запрещён; workflow подтверждения
ещё нужен. Порядок новых invoice reseed выше всех числовых исторических invoice;
вне диапазона bigint — отказ с требованием решения.

Дополнительно сама репетиция проверяет неправильную БД/nonce, искусственный
сбой после purchases, SQL constraint failure, два конкурентных импорта, повтор,
неизменность архива. `test/import.test.js` содержит только искусственные строки.
Источник нельзя передавать frontend, тестовому sender, браузеру или внешним API.
Этот runner предназначен только для локальной репетиции; разрешение/защита
будущего production importer требует отдельного изменения и репетиции.
